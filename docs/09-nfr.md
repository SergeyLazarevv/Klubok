# 9. Нефункциональные требования

## 9.1. Производительность

| Метрика | Цель (MVP) |
|---|---|
| Ответ API, кроме поиска (p95) | < 200 мс |
| Поиск (p95) | < 5 с при прогретом кэше расстояний; жёсткий таймаут 10 с |
| Первая загрузка PWA на 4G | < 3 с |
| Параллельных поисков | 20 (на одном сервере) |

## 9.2. Безопасность

- HTTPS везде (Caddy автоматически выпускает и продлевает сертификаты Let's Encrypt).
- Пароли — argon2id. Никаких паролей и токенов в логах.
- Refresh-токены хранятся в БД только как хэш; ротация при каждом обновлении; повторное использование старого токена отзывает всю цепочку.
- Rate limiting: вход и регистрация — 5 запросов в минуту с IP; поиск — 10 в минуту на пользователя.
- CORS — только свой домен. Заголовки безопасности: CSP, HSTS, X-Content-Type-Options.
- Секреты — переменные окружения; `.env` в `.gitignore`.
- Защита от перебора email при регистрации и восстановлении: одинаковый ответ независимо от существования аккаунта.
- Зависимости проверяются `govulncheck` и `npm audit` в CI.

## 9.3. Персональные данные (152-ФЗ)

Обязательно до запуска для внешних пользователей:
- [ ] Хранение и обработка ПДн граждан РФ — на серверах в РФ (Selectel) ✅ по выбору хостинга.
- [ ] Уведомление Роскомнадзора об обработке ПДн (реестр операторов).
- [ ] Политика обработки персональных данных на сайте.
- [ ] Согласие на обработку ПДн при регистрации (отдельный чекбокс).
- [ ] Удаление аккаунта и всех данных по запросу (AUTH-8).
- [ ] Минимизация: собираем только нужное для расчёта (email, город, параметры авто).

Пока сервисом пользуется только автор — пункты фиксируются как требования, но не блокируют разработку.

## 9.4. Надёжность

- Отказ одного источника цен не ломает поиск (частичный результат).
- Резервное копирование PostgreSQL ежедневно, хранение 14 дней, проверка восстановления раз в месяц.
- Миграции БД — только вперёд, совместимые с предыдущей версией кода.

## 9.5. Наблюдаемость

- Структурированные логи (JSON, `slog`) с `request_id`.
- Метрики Prometheus: латентность API, время ответа и ошибки каждого источника, попадания в кэш.
- Проверки `/healthz` (жив) и `/readyz` (готов: БД и Redis доступны).

## 9.6. Качество кода

- Go: `gofmt`, `golangci-lint`, юнит-тесты на расчёт стоимости и алгоритм поиска (обязательно), интеграционные — с testcontainers.
- Frontend: ESLint, Prettier, `vue-tsc`, Vitest.
- CI (GitHub Actions): линт, тесты, сборка на каждый PR.
- Ветки: `main` защищена, работа через PR.

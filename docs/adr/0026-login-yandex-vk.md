# ADR-0026. Вход через Яндекс ID и VK ID; сессия в cookie, данные — за сессиями пользователя

**Статус:** Принято · 2026-10-21 · заменяет [ADR-0007](0007-auth.md)

## Контекст
По ADR-0007 планировались email с паролем и VK ID, сессии на JWT с refresh-токенами. С тех пор появилось три обстоятельства:
- 149-ФЗ (ст. 10.6, с 01.12.2023) требует авторизовать пользователей российских сайтов через российский номер телефона, Госуслуги или системы российских владельцев. Почта с паролем формально не подходит, Яндекс ID и VK ID подходят.
- Пароли — самая дорогая часть: хэширование, подтверждение почты, сброс пароля, отправка писем, защита от перебора. На телефоне вводить пароль ещё и неудобно.
- Уже есть анонимные сессии (ADR-0018) с избранным и путевыми листами, и при входе их нельзя потерять.

## Решение
- **Способы входа:** Яндекс ID (OAuth 2.0 + PKCE, с `client_secret`) и VK ID (OAuth 2.1 + PKCE, публичный клиент; через него входят и аккаунты OK и Mail.ru). Без SDK, обычными редиректами. Паролей нет.
- **Сессия:** та же cookie `klubok_sid` и таблица `sessions`. Вошедшая сессия — та, у которой есть `user_id`. JWT и refresh-токены не нужны, пока клиент один — PWA на том же домене. Мобильное приложение сможет передавать тот же id в заголовке.
- **При входе — новая сессия** (защита от session fixation). Прежняя анонимная получает `user_id` и закрывается (`ended_at`).
- **Владелец данных — `owner_sessions(сессия)`:** сама сессия плюс все сессии её пользователя. Записи пишутся в текущую сессию и не переносятся. Колонка `favorites.user_id` из ADR-0018 удалена.
- **Дубли после входа:** копия варианта, который у пользователя уже был, удаляется, если к ней не начат путевой лист.
- **Незаконченный вход** (`state`, `code_verifier`, путь возврата) хранится в HttpOnly-cookie на 10 минут. Redis не нужен, а сверка `state` с cookie защищает от login CSRF.
- **Аккаунты по email не склеиваются.** Второй способ входа привязывается явно, из личного кабинета (позже).
- **Токены провайдеров не храним**, из профиля берём id, имя, фото и почту.

Подробно — [12-auth.md](../12-auth.md).

## Последствия
- Вход занимает два нажатия, своих секретов у пользователя нет, писем и SMS не нужно.
- Данные, сохранённые до входа, на любом устройстве и после выхода остаются у пользователя без единой миграции данных.
- Каждый запрос к избранному делает подзапрос по `sessions` (индекс `sessions_user_idx`). На масштабе MVP это незаметно.
- Вход через Яндекс и через VK пока даёт разные аккаунты, пока не сделана привязка.
- Без аккаунта в Яндексе или VK войти нельзя. Если таких пользователей окажется много, добавим вход по телефону.

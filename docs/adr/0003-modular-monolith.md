# ADR-0003. Модульный монолит вместо микросервисов

**Статус:** Принято · 2026-10-12

## Контекст
Рассматривались микросервисы. Команда — один человек, нагрузка — минимальная, домен ещё уточняется.

## Решение
Модульный монолит: одно приложение, модули с явными границами (`auth`, `profile`, `geo`, `road`, `fuel`, `providers`, `search`, `deals`, `notify`). Модули общаются через Go-интерфейсы и не обращаются к таблицам друг друга. Один бинарник в двух ролях: `api` и `worker`.

## Обоснование
- Микросервисы добавили бы сетевые вызовы, распределённые транзакции, отдельные деплои и сложную отладку без какой-либо выгоды на текущем масштабе.
- Чёткие границы модулей сохраняют возможность вынести модуль в сервис позже.

## Последствия
- Кандидаты на вынос при росте: `search` и сборщик цен (`deals`).
- Нужна дисциплина: линтер на запрещённые импорты между модулями (`depguard`).

# ADR-0013. Места на карте из OpenStreetMap: Overpass по запросу, кэш в PostGIS

**Статус:** Принято · 2026-10-12

## Контекст
На карте маршрута нужны заправки, кафе и достопримечательности: вдоль дороги до аэропорта и в городе назначения. Варианты источника: OpenStreetMap (бесплатно, без рейтингов), 2ГИС API и поиск по организациям Яндекса (полнее, но платно; у Яндекса — ограничения на показ не на их картах), Википедия (только заметные места).

## Решение
- Источник — **OpenStreetMap**. Теги: `amenity=fuel`; `amenity=cafe|restaurant|fast_food` с названием; `tourism=attraction|museum|viewpoint|gallery|zoo|theme_park` и `historic=castle|fort|monument|ruins|archaeological_site|manor|monastery` с названием. Мемориалы (`historic=memorial`) не берём — их тысячи, карта превращается в шум.
- Сейчас данные берутся из **Overpass API** при первом запросе области и сохраняются в таблицу `pois`. Область (дорога или окрестность точки) помечается в `poi_scans` и перезагружается раз в 30 дней.
- Запрос к Overpass — по прямоугольникам вокруг кусков маршрута по ~50 км (с отступом 5 км). Запрос «в радиусе от линии» (`around` с линией) на публичных серверах не укладывается в таймаут; прямоугольники отвечают за секунды. Точный коридор (2,5 км для заправок и кафе, 5 км для достопримечательностей) отсекается в PostGIS (`ST_DWithin`).
- Ответ Overpass с `remark` об ошибке (таймаут) считается сбоем и не кэшируется — иначе область запомнится пустой. Временные ошибки (429, 5xx, таймаут) — до 3 попыток; `KLUBOK_OVERPASS_URL` принимает несколько серверов через запятую.
- На мини-карте мест нет — только на полноэкранной: переключатели категорий, кластеры по категориям, карточка места (название, тип, часы работы, ссылки на Википедию, сайт и OSM).

### Подробности о месте (дополнение 2026-10-12)
- Из OSM вместе с местом сохраняются: кухня (`cuisine`), телефон, плата за вход (`charge`, иначе `fee`), ссылки на Wikidata и фото на Commons (`wikimedia_commons`, `image` — только если это Commons: у других сайтов лицензия неизвестна).
- Описание и фото — **на нашей стороне, лениво**: при первом открытии карточки (`GET /pois/{type}/{id}`) сервис идёт по цепочке «статья Википедии → элемент Wikidata → русская статья и фото P18 → первые 3 предложения статьи + уменьшенная копия 640 px с автором и лицензией» и сохраняет результат в `pois` (`details_at`). Следующие пользователи получают его из БД. Заранее обогащать сотни мест, которые никто не откроет, — лишняя нагрузка на Wikimedia.
- Если Википедия не ответила за 10 с — карточка показывается без описания, `details_at` не ставится, загрузка повторится при следующем открытии. Поменялись ссылки в OSM — `details_at` сбрасывается.
- Сами картинки не храним: показываем копию с `upload.wikimedia.org` с подписью «Фото: автор · лицензия» и ссылкой на страницу файла — этого требуют лицензии Commons (CC BY-SA и др.).
- Описание и фото есть примерно у трети достопримечательностей (у тех, что связаны с Википедией). У кафе и заправок — только поля OSM; фото, средний чек и рейтинги — платные источники (2ГИС и др.) `[открыто: этап монетизации]`.

## Последствия
- Первый показ мест по новой дороге — 5–10 секунд, повторный — из БД мгновенно.
- Публичный Overpass нестабилен (за вечер проверки — 504 примерно на каждом втором запросе); для продакшена — импорт выгрузки OSM (Geofabrik, `osmium tags-filter`) в ту же таблицу `pois`. Схема и запросы к БД от этого не меняются, уходит только `Overpass`.
- Рейтингов, отзывов и фото кафе нет; если понадобятся — 2ГИС как дополнительный источник `[открыто]`.
- Подписи на подложке OSM — на местных языках (казахский, персидский и т. п.); русские подписи — вместе с выбором тайл-провайдера (ADR-0012).

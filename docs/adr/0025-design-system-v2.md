# ADR-0025. Дизайн-система v2: токены HSL, тёмная тема, брейкпоинты 375/768/1024/1280, единая анимация

**Статус:** Предложено · 2026-10-20

## Контекст
Интерфейс собран на shadcn-vue ([ADR-0010](0010-ui-tailwind-shadcn-vue.md)), но токены покрывают только цвета светлой темы: тени, длительности и часть цветов заданы по месту в компонентах, кнопки по умолчанию 32 px (меньше 44 px для пальца), таб-бар переключается на 640 px, тёмной темы нет. Приложением пользуются в основном с телефона; нужен современный цельный вид уровня Linear / Vercel / Stripe.

## Решение
Принять спецификацию [11-ui-ux.md](../11-ui-ux.md) поверх текущего стека (Tailwind v4, shadcn-vue, Reka UI, Lucide, Inter):
- нейтральная и акцентная шкалы 50–950 в HSL; семантические токены shadcn ссылаются на них, имена не меняются;
- тени, радиусы (12 / 16 px), стекло, длительности 150/200/300 ms и `cubic-bezier(0.4, 0, 0.2, 1)` — токенами;
- тёмная тема «как в системе» по умолчанию с ручным выбором — **заменяет пункт ADR-0010 «тема только светлая»**;
- брейкпоинты 375 (новый `xs`) / 768 / 1024 / 1280; таб-бар → шапка на 768;
- появление секций — одна директива `v-reveal` на общем IntersectionObserver, с `prefers-reduced-motion`;
- кнопки и поля 44–52 px на телефоне, состояния hover / active / focus-visible / disabled / loading обязательны.

## Последствия
- Переход поэтапный (раздел 11 спецификации), приложение рабочее после каждого шага.
- Вид компонентов из `components/ui` правится локально (cva) — при обновлении через CLI shadcn-vue изменения сливаются вручную.
- Пастельный стиль карты остаётся отдельным; для тёмной темы нужен его тёмный вариант — до этого карта светлая в обеих темах.
- Каждый новый экран проверяется на 320 / 375 / 768 / 1280, в двух темах, с клавиатуры и с уменьшенным движением.

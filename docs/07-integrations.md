# 7. Внешние интеграции

## 7.1. Travelpayouts — цены на авиабилеты (MVP)

Решение: [ADR-0006](adr/0006-travelpayouts-fares.md).

- **Что даёт:** Aviasales Data API — цены из кэша поисков пользователей Aviasales; бесплатный доступ по токену после регистрации.
- **Авторизация:** заголовок `X-Access-Token: <token>` (или параметр `token`).
- **Свежесть:** данные хранятся до 7 дней; цены в рублях на момент попадания в выдачу.
- **Сжатие:** отправлять `Accept-Encoding: gzip, deflate`.
- **Партнёрские ссылки:** нужен `marker` (ID партнёра) — добавляется к ссылке на покупку.

Эндпоинты, которые планируем использовать `[сверить по актуальной документации]`:

| Эндпоинт | Для чего |
|---|---|
| `GET /aviasales/v3/prices_for_dates` | Самые дешёвые билеты по направлению на даты/месяц, туда-обратно, с пересадками — **основной для поиска MVP** |
| `GET /aviasales/v3/grouped_prices` | Цены, сгруппированные по датам — календарь цен (v2) |
| `GET /aviasales/v3/get_latest_prices` | Последние найденные цены — горячие предложения (v2) |
| `GET /v1/city-directions` | Популярные направления из города — топ на главной (v2) |
| `GET /data/ru/cities.json`, `/data/ru/airports.json` | Справочники городов и аэропортов |

Ограничения и риски:
- Цены кэшированные → показываем «от N ₽» и время находки.
- По редким направлениям данных может не быть → честно показываем «нет данных», а не «нет рейсов».
- Поиск в реальном времени (Flight Search API) требует отдельной заявки и объёма трафика — рассматриваем после роста аудитории.

## 7.2. VK ID — вход (MVP)

Решение: [ADR-0007](adr/0007-auth.md).

- Протокол: OAuth 2.1 Authorization Code + **PKCE (S256)** — обязательно.
- Поток: бэкенд генерирует `state` и `code_verifier` → редирект на VK ID → callback с `code`, `state`, `device_id` → обмен кода на токены (с `code_verifier` и `device_id`) → получение профиля (id, имя, email если разрешён) → наша сессия.
- `code_verifier` и `state` хранятся в Redis на 10 минут, привязаны к cookie браузера.
- От VK храним только `provider_user_id`; токены VK не храним (не нужны после входа).
- Домен и параметры эндпоинтов: `[сверить по документации VK ID на dev.vk.com — встречаются id.vk.com и id.vk.ru]`.
- Порядок: VK ID подключаем **последним шагом MVP**, когда будет домен; до этого вход только по email.
- Нужно: создать приложение в кабинете VK ID, указать доверенный redirect URI (`https://<домен>/api/v1/auth/vk/callback`; для локальной разработки — отдельный).

## 7.3. Маршрутизация на машине (MVP)

Решение: [ADR-0009](adr/0009-road-routing.md).

- **OSRM** table-сервис: `GET {KLUBOK_OSRM_URL}/table/v1/driving/{lon,lat;...}?sources=0&annotations=distance,duration`.
- Разработка — публичный демо-сервер (по умолчанию), продакшен — свой экземпляр.
- Кэш — `road_distances`, бессрочно. При недоступности — оценка по прямой × 1,3 (помечается `approximate`).
- Пересечение границы определяем по стране хаба; время на КПП и страховка — из `border_rules`.
- Платные дороги (М-11, М-12 и т.п.): пока не учитываем, в v2 — справочник участков `[открыто]`.

## 7.4. Цены на топливо (MVP — упрощённо)

- Публичного бесплатного API нет.
- MVP: таблица `fuel_prices` (страна, регион, тип топлива), заполняется миграцией — ориентировочные цены по РФ на 2026-10 `[сверить и обновлять]`; пользователь может задать свою цену.
- Парковка у аэропорта: `hub_costs`; пока данных нет — 300 ₽/сутки по умолчанию с пометкой «ориентировочно».
- v2: автоматическое обновление `[открыто: источник]`.

## 7.7. Общие правила для адаптеров

- Каждый источник — отдельный пакет в `internal/providers/<name>`, реализующий общий интерфейс.
- Таймауты, повторы с экспоненциальной задержкой (только для идемпотентных запросов), circuit breaker.
- Ответы источников кэшируются в Redis.
- Секреты — только из переменных окружения, не в репозитории.
- Для тестов — записанные ответы (fixtures), без походов в сеть.
